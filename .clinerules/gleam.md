# Gleam プロジェクトのルール

## 前提
- 言語は Gleam（BEAM 上で動作）。使用ライブラリと版は `gleam.toml` が正。
- ライブラリは新しい版（wisp 2.x、mist 6.x、gleam_stdlib 1.x など）。学習データにある古い API とは異なる。

## API は推測しない
- 関数名・型・引数は、記憶や推測で書かない。
- 使う前に、`build/packages/<ライブラリ名>/src/` の実際のソースを読んで確認する。
- 該当ライブラリのソースが無い場合は `gleam deps download` を実行してから読む。
- 実在しない API（例: Erlang の `httpd`）を FFI で呼ばない。標準ライブラリや依存ライブラリで足りるか、先に探す。

## ビルドで確認する
- コードを変更したら、必ず `gleam build` を実行して結果を確認する。
- コンパイルエラーは、メッセージの内容を読み、該当箇所を直す。
- 同じ修正を 2 回試して直らない場合は、同じ方法を繰り返さず、`build/packages/` のソースを読み直して原因を整理する。
- `gleam build` が通るまで、完了報告しない。
- ロジックを変えた場合は `gleam test` も実行する。

## 書き方
- Gleam に `if` 文・`return`・`null`・例外は無い。`case` 式、`Result`、`Option`、パイプ `|>`、`use` を使う。
- `let assert` は、失敗しないと確実な箇所だけに使う。
- FFI（`@external`）は、Gleam の標準ライブラリで実現できない場合に限る。Erlang 側の関数は `src/*_ffi.erl` に置く。

## ファイル編集のしかた
- 使えるツールは `skills` `read_files` `search_codebase` `fetch_web_content` `editor` `ask_question` `run_commands` の 7 つだけ。`list_directory` `list_files` `replace_in_file` など、これ以外の名前のツールは存在しない。
- ファイルやフォルダの一覧は、`run_commands` で `Get-ChildItem` を実行して取得する。
- ファイル編集は `editor` ツールで行う。`insert_line` は指定しない（行番号を指定した挿入は、1 行ずれるだけで壊れ、行番号の計算で考え込んで進めなくなる）。
- `insert_line` を使わず、`old_text`（置換前の文字列）と `new_text`（置換後の文字列）を指定して置換する。`old_text` は、前後 2〜3 行を含めて、ファイル内で一意になるようにする。
- 大きなファイル（300 行超）の追記は、末尾に追加するか、新しいファイルに分けて `import` する。
- 行数や行番号を数える作業を、思考の中で繰り返さない。必要なら、ファイルを読み直して現在の内容を確認する。
- 同じ文や計算を、思考の中で 2 回以上繰り返していると気づいたら、そこで止めて、ファイルを読み直し、別のやり方に切り替える。

## 完了報告
- 動作確認までできたか、ビルドだけ通ったかを、区別して報告する。
- 直せなかった箇所は、完了扱いにせず、内容と理由を報告する。
