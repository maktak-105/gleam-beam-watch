v1.1 からの変更点:

- ブラウザを開くアカウントを、SYSTEM から `GLOBAL\AAdmZ100DB110` に変える。
- 監視対象は、エイリアスのあるアプリ（エイリアスの URL を開く）と、外部サイト4件だけにする。エイリアスのないポートは外す。
- 死活画面に、エイリアス・アプリ名・転送先を出す。
- 合格条件の件数を 49件から 13件に直す（49件のうち 23件は、2026-11-24 にユーザーが外した）。

## 目的

AI195417 で動いている BEAM Watch の死活を、「ブラウザで URL を開いてページが出たか」で決める。ブラウザはサーバーのオリジナルアカウント `GLOBAL\AAdmZ100DB110` で動かす。画面には、各アプリのエイリアスも出す。

## 現状分析（2026-11-25 に確認した事実）

- 稼働中: タスク `Beam-watch` を SYSTEM で実行している。判定は HTTP の状態コードのまま。監視対象は 26件（OK 11・NG 15）。
- ローカルのコード: ブラウザ判定は実装済み（`gleam test` 3件合格）。SYSTEM では Edge がページを出せない（終了コード 1002）ため、配備していない。
- アカウント: `GLOBAL\AAdmZ100DB110` は Domain Users のみ。2026-11-23 からコンソールにログオンしている。自動ログオンは設定されていない。パスワード保存のタスクで起動すると、Security 4625・状態 0xC000015B（ログオン種別が許可されていない）になる。パスワードは通っている。足りないのは「バッチジョブとしてログオン」（SeBatchLogonRight）の権利で、今は Administrators、Backup Operators、Performance Log Users だけが持っている。GPO では設定されていない（gpresult で確認）ので、ローカルで足しても上書きされない。`C:\server\Apps\beam-watch` には、このアカウントのフルコントロールが継承されている。
- エイリアス: `C:\server\Apps\portal\nginx.conf`（80番、タスク `Portal-Web`）が `http://ai195417/<エイリアス>` を各ポートへ 302 で転送する。アプリ名は `C:\server\Apps\portal\html\index.html` のカードにある。

## 決定事項からの変更（承認をお願いしたい点）

「人事DB の証明書を AAdmZ100DB110 だけに信頼させる」は、選んでいただいた方法（そのユーザーの「信頼されたルート証明機関」に入れる）ではできない。非対話のセッションからこのストアへ入れると、「この操作で UI は使用できません」で拒否される（2026-11-25 に私のアカウントで確認済み。証明書は残っていない）。入れるには、誰かがコンソールで AAdmZ100DB110 として確認ダイアログの「はい」を押す必要がある。

代わりに、BEAM Watch が起動する Edge にだけ、`--ignore-certificate-errors-spki-list=<人事DB 証明書の公開鍵のハッシュ>` を付ける。信頼するのは、BEAM Watch が開くブラウザと、この公開鍵の証明書だけ。証明書ストアは変えない。サーバーで試したところ、`https://ai195417:8766/` と `http://ai195417/jinji` のどちらでも、ページ（「試作部 人事リスト」）が出た。証明書を作り直すと公開鍵が変わり、NG（証明書が信頼されていない）になる。そのときは画面でわかる。

## リスク

- 試せていないこと: AAdmZ100DB110 のバッチログオン（タスク）で Edge がページを出せるかは、権利を足すまで試せない。私のアカウントの WinRM（同じセッション0）では出た。出なかった場合は、手順 4 の時点で止めて戻し、結果に書く。
- パスワードの変更: タスクに保存したパスワードが変わると、タスクが起動できなくなり、8010 も止まる。パスワードの有効期限は「なし」（net user で確認）。
- 外部サイト: fieldstyle と shadowing は、AI195417 からだと接続が切られる（`ERR_CONNECTION_RESET`）。サーバーのブラウザでもページが出ないので、NG とその理由が出る。BEAM Watch では直せない。camp は時間によって変わる。
- 1周の時間: 13件を 4件ずつ開くので、1件40秒を上限として最大約160秒。間隔の 300秒に収まる。
- コンソールの AAdmZ100DB110 の Edge とは、ユーザーデータのフォルダを分けるので干渉しない。BrowserCheck が止めるのは、自分が作ったフォルダを使う Edge だけ。
