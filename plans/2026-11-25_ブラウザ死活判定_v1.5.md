# 計画書: ブラウザで開いた結果を死活にする(v1.5)

v1.4 の配備後に残った課題 1・2 を直す（`plans/2026-11-25_ブラウザ死活判定_結果_v1.1.md` の残課題）。ユーザーの指示「1と2も直して」（2026-11-25）を承認として扱う。ここに書いていないことは v1.4 のとおり。

## 1. エラーページも OK になる

- 現状: `BrowserCheck.ps1` は、ページが出てボット確認画面でなければ OK にする。nginx の 404 ページ（`http://ai195417/nothing-here`、タイトル「404 Not Found」）も OK になる。
- 変更: ブラウザに出たページのタイトルと最初の `<h1>` が HTTP のエラーページなら NG にする。理由は `エラーページが出た (<タイトル>)`。エラーページとみなす条件は次のどれか。
  - 先頭が 4xx/5xx の番号（例: `404 Not Found`、`502 Bad Gateway`、`404: This page could not be found.`）
  - `HTTP Error 4xx/5xx` で始まる（IIS）
  - 全体が `Not Found`、`Bad Gateway`、`Service Unavailable`、`Internal Server Error`、`Gateway Timeout`（`Time-out` を含む）、`Server Error`、`Forbidden`、`Error response` のどれか（Laravel、Python など）
- 状態コードは見ない。ブラウザに出たページの中身で決める。

## 2. 「今すぐチェック」が 500 になる

- 現状: `POST /api/check` は、チェックが終わるまで応答を待つ（上限 120秒）。1周は約70秒なので、チェック中に押すと、今の1周と次の1周を待って上限を超え、500 になる。
- 変更（`src/gui_server.gleam`）:
  - `POST /api/check` はすぐ返す。チェック中でなければ始めて `started`、チェック中なら `queued` を返す（202）。
  - チェック中に「今すぐチェック」・URL の追加・自動チェックの時刻が来たら、今の1周が終わったあとにもう1周する（何回来ても1周だけ）。今は、チェック中に追加した URL は次の自動チェックまで確認されない。
  - `GET /api/results` に `checking`（チェック中か）を足す。
- 変更（`gui/script.js`）: 「今すぐチェック」で警告を出さない。監視結果の見出しの横に、チェック中は「チェック中…」と出す。

## 検証方法

1. `gleam format --check` と `gleam test` が通る。チェックの受付（started / queued）と、2つ目の周回をテストに足す。
2. サーバー上で `BrowserCheck.ps1` を私のアカウントで実行し、`http://ai195417/nothing-here` が NG（エラーページが出た (404 Not Found)）、エイリアスの 9件が OK のままであることを確かめる。
3. `Publish-ToServer.ps1` で配備する。
4. 「今すぐチェック」を続けて2回押す（API）。1回目は 202 `started`、2回目は 202 `queued` で、どちらもすぐ返る。チェック中は `/api/results` の `checking` が true、終わると false になり、9件の確認日時が2周分進む。
5. 画面で「チェック中…」の表示と、9件の OK を確かめる。

## リスク

- タイトルによる判定なので、アプリの正規のページのタイトルが「Not Found」などの場合は NG になる。今の 9件は配備前に確かめる。
- 自動チェックの間隔を 1秒にすると、チェックが終わるたびにすぐ次の1周が始まる（今も間隔どおり動くだけで、変わらない）。
